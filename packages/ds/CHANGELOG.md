## 0.2.0
Fri, 07 Aug 2026 13:15:02 GMT

### Minor changes

- Adds the form and action tier: `Checkbox`, `Radio`, `RadioGroup`, `Switch`, `Slider`, `FormField`, `Fieldset`, `IconButton` and `ButtonGroup`.

Every control is a native element, tinted with accent-color rather than replaced. A div dressed as a checkbox has to re-implement keyboard handling, the indeterminate state, form participation and every assistive-technology behaviour the native control already has, and usually re-implements only some of them.

FormField hands its child the wiring through a render function rather than cloning it: the id, the aria-describedby pointing at hint and error, and aria-invalid. Cloning reads more tidily and breaks the moment a caller wraps their control in a fragment or a component of their own, because the props land on the wrapper and nothing reports it. The error region is always rendered and carries role=alert, so a message appearing after a failed submit reaches a reader who has already moved past the field.

Fieldset and RadioGroup use a real fieldset and legend, the one construct that gets a group name announced before each control inside it. RadioGroup does not set the shared name on its children, for the same reason FormField does not clone: it is documented instead. Switch is a checkbox carrying role=switch, which is what makes a reader hear on and off rather than checked and unchecked. Slider takes a valueText for scales where the bare number says nothing. IconButton requires its label and renders it visually hidden, because an icon button with no accessible name is announced as 'button' and nothing else — so the component does not offer the option of omitting it.
- Adds fifteen primitives: `Stack`, `Inline`, `Grid`, `Container`, `Divider`, `Card`, `Heading`, `Text`, `Link`, `InlineCode`, `Kbd`, `Spinner`, `Skeleton`, `EmptyState` and `VisuallyHidden`.

Spacing is passed per instance as a custom property rather than through modifier classes. Fourteen scale steps across five layout components would be seventy rules shipped to every consumer; one declaration reading a variable is a single rule, and still loses to a class the caller writes.

The accessibility decisions live in the API rather than being left to each call site. Spinner announces through a status role with a visually-hidden label defaulting to 'Loading', because an indicator nobody can perceive is worse than none. Skeleton is hidden from assistive technology, since announcing a row of grey boxes tells a screen-reader user nothing they can act on. Heading takes a visual size independent of its outline level, so a section that should look small stays the heading it structurally is, and EmptyState takes a configurable heading level for the same reason. Divider is an hr horizontally and a separator role vertically, because a thematic break turned on its side is not one. Link applies noopener with a blank target, which is a hole rather than a preference. Both animations stop under prefers-reduced-motion.

The package also gains TypeDoc, which it never had: eighty-five pages generated with no warnings, every component carrying a worked example. Types referenced by public props but never exported — button variant and size, callout kind, field size, alignment, the theme context — are now exported, since a prop whose type cannot be named is a prop nobody can type against.
- Add the anchored overlay tier: `Popover`, `Menu`, `MenuItem`, `MenuSeparator`, `ContextMenu` and `Tooltip`, plus the pure `resolvePlacement` they position with.\n\nUnlike the modal tier these are non-modal — they sit beside the page rather than over it, so they trap nothing and lock nothing. They close on Escape, on an outside press, and when focus leaves for something that is neither the surface nor its trigger. `Menu` adds the menu keyboard pattern: focus moves to the first item on open and roves with the arrows, Home and End, wrapping at both ends, while Tab closes and continues past the trigger.\n\nEach takes a `trigger` render prop and hands it the ARIA wiring rather than documenting it. `aria-expanded`, `aria-haspopup` and `aria-controls` are the step that gets skipped, and a screen reader then describes a button that appears to do nothing. `aria-controls` is only emitted while the surface exists, so it never dangles.\n\nA disabled `MenuItem` carries `aria-disabled` rather than the `disabled` attribute, so the arrow keys still reach it: being told an action is unavailable is better than being unable to find out it exists.\n\n`Tooltip` is uncontrolled, because a tooltip's visibility belongs to the pointer and the focus ring rather than to application state. It never takes focus, is wired with `aria-describedby` rather than `aria-label` — labelling with one leaves an icon button whose name vanishes with the tooltip — and stays off the shared dismissal stack so it cannot swallow an Escape meant for a dialog underneath it.\n\n`resolvePlacement` is exported and pure. It flips only when the opposite side actually fits; flipping to whichever side merely has more room moves an overlay taller than the window for a few percent of visible area and makes the position unpredictable. Clamping is cross-axis only, since clamping the main axis would slide the overlay over the element it describes. Coordinates are viewport-relative against `position: fixed`, so no offset-parent arithmetic is involved.\n\nThe `/client` size budget rises from 4 KB to 5.5 KB to match. `{ Dialog }` on its own did not move, which is the tree-shaking claim holding as the tier grew.
- Add the modal overlay tier: `Portal`, `Dialog` and `Drawer`, published from `@yoltra/ds/client`.\n\nOverlays render into a node under `document.body` rather than where they are written, because rendering in place loses to CSS three ways that no `z-index` fixes: an ancestor with `overflow: hidden` clips the panel, an ancestor with `transform`, `filter` or `will-change` becomes the containing block for `position: fixed` so a viewport-centred dialog is centred in that ancestor instead, and an ancestor that established a stacking context traps the overlay beneath whatever sits above it.\n\nA new `zIndex` scale joins the foundation tokens and emits as `--yl-z-*`. Portalled surfaces land in the document's stacking order, so their order depends on nothing but these numbers; the scale encodes containment, with a popover above a dialog and a tooltip above both.\n\nThe surfaces are controlled — `open` and `onClose` are the whole state contract — and carry the behaviour that separates a usable overlay from a visible one: focus trapped inside and restored on close, page scroll locked under a reference count so nesting cannot leave it stuck, and Escape and outside-press dismissal routed through a shared stack so one keystroke closes one layer rather than every layer listening at once.\n\n`title` is required rather than optional: a modal with no accessible name is announced as \"dialog\" and nothing else.\n\nThe size budget now measures the `/client` entry, which nothing checked before, and the CSS invariant test scans the overlay stylesheets alongside the primitives.
- Component styles move from a generated string to SASS, and ship as one stylesheet per component.\n\n`themeCss()` used to return the custom properties *and* every component's rules, so an application importing one Button shipped the styles for the table, the tabs and the code block as well. The JavaScript tree-shakes; a single stylesheet cannot. Styles are now authored in SASS under `src/primitives/<Component>.scss` and compiled to `dist/styles/<component>.css`, imported individually. `all.css` carries everything for consumers who would rather not choose.\n\nSASS never owns a value: colours, spacing and radii are read as `var(--yl-*)`, because theming is a runtime `data-theme` switch and a SASS variable compiles away before that switch can reach it. What it contributes is nesting, per-component files, and shared mixins for the focus ring, visually-hidden text and breakpoints.\n\nLengths are now emitted in `rem` against a 10px root — `base.css` sets `html { font-size: 62.5% }`, so `--yl-space-4` is `1.6rem`. Tokens stay authored in pixels and only the output carries the unit. Breakpoints and hairline borders deliberately stay in pixels: `rem` in a media query resolves against the initial root rather than this one, and a 1px border should not invite sub-pixel rounding. `base-no-root.css` omits the root declaration for an application that sets its own.\n\n**Breaking**: `themeCss()` no longer includes component styles. Replace a single call with the token and base sheets plus the components in use, or with `all.css`.
- Open the table subcomponents to their native attributes: THead, TBody, TR, TH and TD accepted only children, so a header cell could not carry scope — the attribute that lets assistive technology associate a data cell with its header — and a cell could not span columns without dropping to a raw element. Each now extends its proper HTML attribute type and spreads, matching how every other primitive in the package already behaves, and TH's docs say why scope is not optional in spirit.

### Patches

- Declares a bundle-size budget, checked by `rush size` against the package bundled the way a consumer ships it — tree-shaken, minified and gzipped — rather than against the unminified file in `dist`, which measures nothing anybody downloads.
- Tests the design system, which had none.

110 tests at 96.1% statements and 93.9% branches, with thresholds set at that floor. They cover every component's rendered element and class composition, the accessibility wiring for the form tier, the two interactive components behind the client entry, and the token and theme invariants.

The one worth naming is a stylesheet invariant: every var(--yl-*) a compiled component reads must be a property the token emitter defines. A typo in a custom property does not fail anything — it compiles, ships, and renders as though the declaration were absent, on one component, in one theme. Writing the check found exactly that: --yl-color-bg-surface never existed, so every Card fell through to its fallback and rendered the same colour as the page behind it. The theme defines bg-panel for precisely this, and Card now uses it.

Two more dead fallbacks went the same way. The rule is now that anything in a token namespace must resolve whether or not it has a fallback; only component-local properties, which a component sets per instance, may be undefined.

The size budget is re-based and split: a typical four-component import is 2.4 KB against a 5.4 KB barrel, and the gap between them is the tree-shaking claim being checked rather than asserted.

## 0.1.0
Fri, 10 Jul 2026 07:51:29 GMT

### Minor changes

- Initial release of @yoltra/ds — the Yoltra Design System, the shared visual language for the website, documentation, and examples. Ships foundation tokens (a 10-step color palette anchored on brand blue #1A7FE2, typography on Inter + JetBrains Mono, and spacing / radius / elevation / motion scales), light and dark semantic themes that map those primitives to intent-based roles (background / foreground / border / interactive / status), a themeCss() generator that emits --yl-* CSS custom properties for both themes plus base component styles, and primitive React components: Button, ButtonLink, Badge, Callout, Table (with THead/TBody/TR/TH/TD), CodeBlock, and Tabs. Theming is driven entirely by a data-theme attribute on the document root, so components resolve colors through CSS variables and render on the server without a React context.

### Patches

- Split interactive components behind a dedicated "@yoltra/ds/client" subpath entry (ThemeProvider, useTheme, applyTheme, CodeBlock, Tabs) that carries the "use client" directive, so the default "@yoltra/ds" entry stays safe to import from React Server Components (for themeCss() and the static primitives). The package "exports" map declares both "." and "./client", each with types + import + require conditions.
